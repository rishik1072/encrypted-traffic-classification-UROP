# Chapter 5: Dataset Provenance & Characterization

## 5.1 The Need for an Authoritative Real-World Benchmark

Machine learning models are fundamentally constrained by the quality and realism of their training data. In network security and traffic analysis, researchers frequently face a dilemma: public datasets (e.g., ISCX-VPN-2016, USTC-TFC-2016) often lack modern protocol versions (e.g., TLS 1.3, QUIC, WireGuard), contain outdated cipher suites, or exhibit severe topological leakage where individual IP addresses uniquely correlate with target classes. Conversely, synthetic packet generators (such as Scapy-generated fixtures) lack physical network dynamics.

To establish an empirical benchmark free of topological shortcuts and evaluate model robustness under diverse network dynamics, we developed **`dataset_v2`**, a multi-environment hybrid benchmark combining 121 physical Wi-Fi flows (40.2%) captured from an operational Windows 11 workstation with 180 controlled statistical feature perturbations (59.8%) modeling alternative physical interfaces and network impairments.

## 5.3 Target Traffic Classes

`dataset_v2` comprises 301 valid, bidirectional flows balanced across six canonical application categories:

1. **Web Browsing (`Web`, $N=50$ flows):** Interactive HTTPS/QUIC traffic generated by modern browsers (Google Chrome, Mozilla Firefox) navigating dynamic websites (e.g., Wikipedia, e-commerce, news portals), characterized by bursty, request-response transaction patterns.
2. **Video Streaming (`Video`, $N=50$ flows):** Continuous media streaming over HTTPS and QUIC (YouTube, Netflix, Vimeo) operating with Adaptive Bitrate (ABR) chunking, exhibiting large downstream burst sizes separated by periodic buffer-refill intervals.
3. **Instant Messaging (`Messaging`, $N=50$ flows):** Low-bandwidth signaling, WebSocket connections, and intermittent message exchanges (Signal, Telegram, WhatsApp Web), characterized by small, sporadic payloads and long idle keep-alive intervals.
4. **Voice over IP (`VoIP`, $N=50$ flows):** Real-time interactive voice and video communications (Zoom, Microsoft Teams, WebRTC) utilizing RTP/SRTP or UDP transport, exhibiting tight, symmetric inter-arrival times and small packet sizes.
5. **Bulk File Transfer (`File Transfer`, $N=50$ flows):** High-throughput data transfers via SFTP, HTTPS large-file downloads, and cloud storage synchronization (Google Drive, OneDrive), characterized by maximum-length TCP segments and persistent downstream bandwidth saturation.
6. **Other Background Traffic (`Other`, $N=51$ flows):** Diverse background services, software update daemons, NTP synchronization, and telemetry flows, serving as a realistic negative/heterogeneous class.

## 5.4 Multi-Environment Testbed and Perturbation Model

Physical baseline data collection was executed on a workstation running Microsoft Windows 11 Enterprise x64:

- **Physical Wi-Fi Environment (`env_win11_wifi`):** 802.11ax (Wi-Fi 6) wireless connection to an enterprise access point, recorded via Scapy/Npcap ring buffer on 2026-08-23 under Cloudflare WARP tunneling (121 physical flows, 60 sessions).
- **Simulated Gigabit Ethernet (`env_win11_eth`):** 60 flows (30 sessions) generated via bounded numerical feature perturbations of physical prototypes, modeling reduced inter-packet jitter and higher sustained burst densities.
- **Simulated Cellular LTE (`env_win11_cellular`):** 60 flows (30 sessions) generated via feature perturbations modeling carrier-grade NAT buffering, mobile scheduling variance, and increased latency tail quantiles.

### Tunneling Encapsulation: Direct vs. WireGuard (WARP)
- **Tunneled Traffic (`warp_enabled`, 265 flows):** All 121 physical flows plus 144 perturbed flows. Inner transport segments are encapsulated in WireGuard UDP datagrams targeting Cloudflare edge nodes.
- **Direct Traffic (`warp_disabled`, 36 flows):** Modeled via statistical feature scaling of prototypes to evaluate unencapsulated direct transport.

## 5.5 Data Hygiene and Leakage Prevention

To prevent data snooping and ensure scientific validity, the following safeguards were enforced:

1. **Topological Shortcut Excitation:** All Layer-3 IP addresses (source and destination), Layer-4 port numbers, Ethernet MAC addresses, and absolute Unix timestamps were scrubbed from all training and evaluation matrices. Classifiers operate strictly on statistical distributions (e.g., packet length variance, inter-arrival time quantiles, forward/backward ratios).
2. **Session and Capture Tagging:** Every flow was tagged with a unique `session_id` and `capture_file` identifier. As detailed in Chapter 6, all train/validation/test partitions are partitioned strictly at the session level to ensure zero cross-partition leakage.
3. **Payload Sanitization:** Raw packet payloads were discarded at the capture tap; zero payload bytes were saved to disk or loaded into memory.
